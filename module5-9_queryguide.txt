==================================================
 모듈 5. 포인트 시스템 (Point)
==================================================

[5-1] 포인트 잔액 조회
SELECT point_balance FROM user WHERE user_id = ?;

   순서   값         타입
   1      user_id    int


[5-2] 포인트 적립·차감 (내역 기록 + 잔액 갱신)
포인트 변동은 아래 두 쿼리를 항상 함께 실행
적립은 point_amount 양수, 차감은 음수로 넣어 잔액에 그대로 더함

   내역 기록
INSERT INTO point_history (user_id, point_type, point_amount) VALUES (?, ?, ?);

   순서   값             타입
   1      user_id        int
   2      point_type     String   (출석체크 / 랭킹 / 좋아요 등)
   3      point_amount   int      (적립 양수, 차감 음수)

   잔액 갱신
UPDATE user SET point_balance = point_balance + ? WHERE user_id = ?;

   순서   값             타입
   1      point_amount   int      (위 내역과 같은 값, 차감이면 음수)
   2      user_id        int

   차감(구매 등) 전에는 5-1로 잔액이 부족하지 않은지 먼저 확인


[5-3] 포인트 내역 조회
SELECT point_id, point_type, point_amount, created_at FROM point_history WHERE user_id = ? ORDER BY created_at DESC;

   순서   값         타입
   1      user_id    int


==================================================
 모듈 6. 커뮤니티 (Community)
==================================================

[6-1] 게시글 작성
INSERT INTO post (user_id, content) VALUES (?, ?);

   순서   값         타입
   1      user_id    int
   2      content    String

   like_count는 기본값 0, created_at은 자동 기록이라 넣지 않음


[6-2] 게시글 수정
UPDATE post SET content = ? WHERE post_id = ?;

   순서   값         타입
   1      content    String
   2      post_id    int


[6-3] 게시글 삭제
DELETE FROM post WHERE post_id = ?;

   순서   값         타입
   1      post_id    int


[6-4] 전체 피드 조회 (작성자명 포함, 최신순)
SELECT p.post_id, p.user_id, u.user_name, p.content, p.like_count, p.created_at FROM post p JOIN user u ON p.user_id = u.user_id ORDER BY p.created_at DESC;

   파라미터 없음


[6-5] 좋아요 등록 (중복 방지 + 카운트 증가)
아래 두 쿼리를 함께 실행
post_like에 (post_id, user_id) 복합 UNIQUE가 걸려 있어, 이미 누른 경우
INSERT가 실패(중복 에러)하므로 그때는 카운트 증가를 하지 않음

   좋아요 기록
INSERT INTO post_like (post_id, user_id) VALUES (?, ?);

   순서   값         타입
   1      post_id    int
   2      user_id    int

   카운트 증가
UPDATE post SET like_count = like_count + 1 WHERE post_id = ?;

   순서   값         타입
   1      post_id    int

   좋아요 시 게시글 작성자에게 포인트 적립(5-2)을 함께 처리


[6-6] 좋아요 취소 (기록 삭제 + 카운트 감소)
   기록 삭제
DELETE FROM post_like WHERE post_id = ? AND user_id = ?;

   순서   값         타입
   1      post_id    int
   2      user_id    int

   카운트 감소
UPDATE post SET like_count = like_count - 1 WHERE post_id = ?;

   순서   값         타입
   1      post_id    int


[6-7] 내가 이 글에 좋아요 눌렀는지 확인
SELECT COUNT(*) AS cnt FROM post_like WHERE post_id = ? AND user_id = ?;

   순서   값         타입
   1      post_id    int
   2      user_id    int

   cnt가 1이면 이미 누름(하트 채움), 0이면 안 누름

 모듈 7. 친구 관리 (Friend)
==================================================

[7-1] 친구 요청 보내기
INSERT INTO friend (user_id, friend_user_id, status) VALUES (?, ?, '요청');

   순서   값                타입
   1      user_id           int   (요청하는 사람)
   2      friend_user_id    int   (요청받는 사람)

   (user_id, friend_user_id) 복합 UNIQUE라 중복 요청은 INSERT 실패


[7-2] 친구 요청 수락
UPDATE friend SET status = '수락' WHERE friend_id = ?;

   순서   값           타입
   1      friend_id    int


[7-3] 친구 삭제 / 요청 거절
DELETE FROM friend WHERE friend_id = ?;

   순서   값           타입
   1      friend_id    int


[7-4] 내 친구 목록 조회 (수락된 친구)
SELECT f.friend_id, u.user_id, u.user_name FROM friend f JOIN user u ON f.friend_user_id = u.user_id WHERE f.user_id = ? AND f.status = '수락';

   순서   값         타입
   1      user_id    int


[7-5] 받은 친구 요청 목록
SELECT f.friend_id, u.user_id, u.user_name FROM friend f JOIN user u ON f.user_id = u.user_id WHERE f.friend_user_id = ? AND f.status = '요청';

   순서   값         타입
   1      user_id    int   (요청받은 나 자신)

 모듈 8. 팀 챌린지 (Challenge)
==================================================

[8-1] 팀룸 생성
INSERT INTO team_room (owner_id, room_name, start_date, end_date) VALUES (?, ?, ?, ?);

   순서   값            타입
   1      owner_id      int
   2      room_name     String
   3      start_date    Date
   4      end_date      Date


[8-2] 팀룸 참여 (멤버 등록 + 개인 목표금액)
INSERT INTO team_member (room_id, user_id, goal_amount) VALUES (?, ?, ?);

   순서   값             타입
   1      room_id        int
   2      user_id        int
   3      goal_amount    int   (해당 멤버의 목표 지출 금액)

   (room_id, user_id) 복합 UNIQUE라 같은 방 중복 참여는 실패


[8-3] 내가 참여한 팀룸 목록
SELECT r.room_id, r.room_name, r.start_date, r.end_date, r.owner_id FROM team_room r JOIN team_member tm ON r.room_id = tm.room_id WHERE tm.user_id = ?;

   순서   값         타입
   1      user_id    int


[8-4] 챌린지 순위 (절약액 = 목표금액 - 실제지출, 많을수록 우승)
SELECT tm.user_id, u.user_name, tm.goal_amount, COALESCE(SUM(e.expense_amount),0) AS spent, tm.goal_amount - COALESCE(SUM(e.expense_amount),0) AS saved FROM team_member tm JOIN user u ON u.user_id = tm.user_id JOIN team_room r ON r.room_id = tm.room_id LEFT JOIN expense e ON e.user_id = tm.user_id AND e.spent_date BETWEEN r.start_date AND r.end_date WHERE tm.room_id = ? GROUP BY tm.user_id, u.user_name, tm.goal_amount ORDER BY saved DESC;

   순서   값         타입
   1      room_id    int

   챌린지 기간(start_date~end_date)은 team_room 값을 그대로 사용
   결과 첫 행이 우승자(절약액 최대). saved가 음수면 목표 초과

   순서   값                 타입

 통계 · 랭킹 (Dashboard)
==================================================

[S-1] 전체 절약왕 랭킹 (수입 대비 지출률, 낮을수록 상위)
SELECT u.user_id, u.user_name, u.income, COALESCE(SUM(e.expense_amount),0) AS spent, ROUND(COALESCE(SUM(e.expense_amount),0)*100.0/NULLIF(u.income,0),1) AS spend_rate FROM user u LEFT JOIN expense e ON e.user_id = u.user_id AND e.spent_date BETWEEN ? AND ? GROUP BY u.user_id, u.user_name, u.income ORDER BY spend_rate ASC;

   순서   값         타입
   1      시작일     Date
   2      종료일     Date

   spend_rate 오름차순 = 수입 대비 적게 쓴 사람이 상위
   상위 n명에게 포인트 지급은 결과를 받아 Java에서 처리(5-2)


[S-2] 또래 나이대 평균 대비 내 지출 상위%
나이대 구간(from~to)은 Java에서 판정해 전달
 (17~19 / 20~24 / 25~29 / 30~34 / 35~40)
상위% = rank_high / group_cnt * 100, 최종 계산은 Java에서

WITH age_group AS (
  SELECT u.user_id, COALESCE(SUM(e.expense_amount),0) AS spent
  FROM user u
  LEFT JOIN expense e ON e.user_id = u.user_id AND e.spent_date BETWEEN ? AND ?
  WHERE (YEAR(CURDATE()) - YEAR(u.birth_date)) BETWEEN ? AND ?
  GROUP BY u.user_id
)
SELECT
  (SELECT spent FROM age_group WHERE user_id = ?) AS my_spent,
  (SELECT ROUND(AVG(spent),0) FROM age_group) AS avg_spent,
  (SELECT COUNT(*) FROM age_group) AS group_cnt,
  (SELECT COUNT(*) FROM age_group WHERE spent >= (SELECT spent FROM age_group WHERE user_id = ?)) AS rank_high;

   순서   값             타입
   1      시작일         Date
   2      종료일         Date
   3      나이대 하한     int    (예: 30)
   4      나이대 상한     int    (예: 34)
   5      user_id        int
   6      user_id        int    (5번과 동일 값)


[S-3] 고정지출 분석 (최근 3개월 매달 반복된 항목 추출)
중분류 + 금액이 동일하게 3개월 모두 등장한 항목을 고정지출 후보로 반환
결과를 사용자에게 보여주고, 실제 고정지출은 체크박스로 확정(expense.is_fixed UPDATE)

SELECT m.medium_name, e.expense_amount, COUNT(DISTINCT DATE_FORMAT(e.spent_date, '%Y-%m')) AS months FROM expense e JOIN medium_category m ON e.medium_id = m.medium_id WHERE e.user_id = ? AND e.spent_date >= ? GROUP BY e.medium_id, e.expense_amount HAVING COUNT(DISTINCT DATE_FORMAT(e.spent_date, '%Y-%m')) >= 3;

   순서   값             타입
   1      user_id        int
   2      기준시작일      Date   (오늘 기준 3개월 전, Java에서 계산)
